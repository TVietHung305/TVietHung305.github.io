Networking · Wireshark

Packet Analysis

Notes on local networking, TCP connections and packet inspection with Wireshark.

Local Server

The IPv4 range 127.0.0.0/8 is reserved for loopback communication. Addresses in this range refer to the local host rather than an external network destination.

The address 127.0.0.1 is commonly used to communicate with services running on the same machine. The hostname localhost normally resolves to this loopback address.

Observing Packets

When starting a capture in Wireshark, each listed interface represents a network connection provided by hardware or software. For example, an Ethernet interface may be the network adapter used by a virtual machine.

TCP Three-Way Handshake

TCP establishes a connection through a three-way handshake. The handshake allows both sides to synchronize their initial sequence numbers and establish the connection.

  1. The client sends a packet with the SYN flag.
  2. The server responds with SYN and ACK.
  3. The client sends an ACK packet.

Identifying Packets with Data

The packet length field can help determine whether a packet contains application data. The initial TCP handshake packets primarily establish the connection and do not necessarily carry application payload.

The PSH flag indicates that the receiving TCP implementation should push received data toward the application rather than waiting for additional buffering. It is useful when examining packets that carry application data, although it does not mean that every packet with PSH is a complete application message.

In Wireshark, the following display filter can be used to find packets with the PSH flag set: 

tcp.flags.push == 1

Packet Structure

Selecting a packet in Wireshark displays its protocol structure as a series of layers. Depending on the captured traffic, these may include Ethernet, IP, TCP and application protocol fields.

Understanding the Traffic Flow

A single packet does not always provide enough information to understand what an application is doing. Application data may be split across multiple packets, and the meaning of a packet is often clearer when viewed as part of the complete communication flow.

Instead of analyzing each packet in isolation, it is useful to follow the direction of communication and correlate packets from the client and server.

A simplified traffic sequence from the original notes:

  1. Client → Server: Packet 1
  2. Server → Client
  3. Client → Server: Packet 2
  4. Server → Client
  5. Client → Server: Packet 3

Takeaways

  • Choose the correct network interface before capturing traffic.
  • Understand the TCP handshake before interpreting application data.
  • Use display filters to narrow down relevant packets.
  • Analyze packet sequences as a complete flow instead of relying on isolated packets.
