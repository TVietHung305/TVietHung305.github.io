Memory Scanner

Notes on the architecture of a basic Windows process memory scanner.

Introduction

Cheat Engine is a well-known example of a memory scanner. Memory scanners allow users to search for values stored in a process's memory and inspect how those values change.

Understanding the Search Process

The basic idea is to search a target process for a particular value and record the addresses where that value appears. A later scan can examine only the previously identified addresses, narrowing down the candidate list.

For example, a 32-bit process has a virtual address space that can be represented by a range of addresses. A scanner can examine readable memory regions and compare DWORD-sized values against a requested value.

A filtering pass then checks the addresses found in the previous scan. Addresses whose current values no longer match are discarded.

Program Structure

The scanner can be divided into three logical operations:

  • Search: identify candidate addresses.
  • Filter: recheck previously identified addresses.
  • Write: update a value in an authorized test process.

Command-line arguments can select which operation to run. A results file can be used to pass candidate addresses from one scan operation to the next.

Process Handle

Windows process memory APIs operate on a process handle. A process snapshot can be used to enumerate processes and identify a target process in a controlled test environment. 

#include <windows.h>
#include <tlhelp32.h>
#include <stdio.h>

int main(int argc, char** argv) {
    HANDLE process_snapshot = 0;
    PROCESSENTRY32 pe32 = { 0 };

    pe32.dwSize = sizeof(PROCESSENTRY32);

    process_snapshot =
        CreateToolhelp32Snapshot(TH32CS_SNAPPROCESS, 0);

    if (process_snapshot == INVALID_HANDLE_VALUE) {
        return 1;
    }

    if (Process32First(process_snapshot, &pe32)) {
        do {
            if (wcscmp(pe32.szExeFile, L"test.exe") == 0) {
                /*
                 * Open only a process that you own
                 * or are explicitly authorized to inspect.
                 */

                HANDLE process = OpenProcess(
                    PROCESS_QUERY_INFORMATION |
                    PROCESS_VM_READ,
                    FALSE,
                    pe32.th32ProcessID
                );

                if (process != NULL) {
                    /* Perform authorized inspection here. */

                    CloseHandle(process);
                }

                break;
            }
        } while (Process32Next(process_snapshot, &pe32));
    }

    CloseHandle(process_snapshot);
    return 0;
}

Search Operation

The search operation examines readable memory regions and compares values against the requested DWORD. A process does not necessarily have every address in its virtual address space committed or readable, so memory inspection must account for inaccessible regions.

ReadProcessMemory can read a requested range into a local buffer. Its return value and the number of bytes read should be checked before interpreting the buffer.

Memory regions can be enumerated with VirtualQueryEx. This provides information about the state and protection of each region, allowing an inspection tool to distinguish readable memory from inaccessible memory.

Filtering

Filtering uses the candidate addresses from a previous search. The scanner reads the current value at each candidate address and keeps only addresses that still match the requested value.

A temporary results file can be used to store the filtered list before replacing the previous results. This makes it possible to repeat the filtering operation as the target process changes.

Writing

The original notes also describe a write operation using WriteProcessMemory. Writing to another process changes its state and should only be performed in a controlled test process that you own or are authorized to modify.

A robust implementation should validate the target address, requested size, process handle and number of bytes written. It should also make the write operation an explicit action, rather than silently modifying memory during a scan.

Important APIs

  • CreateToolhelp32Snapshot — creates a snapshot for process enumeration.
  • Process32First and Process32Next — enumerate processes.
  • OpenProcess — opens a process with requested access rights.
  • VirtualQueryEx — queries information about a process memory region.
  • ReadProcessMemory — reads memory from another process.
  • WriteProcessMemory — writes memory to another process.

Takeaways

The most important part of a memory scanner is not simply iterating through addresses. It is understanding virtual memory regions, process access rights, read failures and how candidate addresses are maintained across multiple scans.
