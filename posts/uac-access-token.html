Exploring UAC and Access Tokens

Notes on Windows User Account Control and access token concepts.

UAC (User Account Control)

User Account Control (UAC) is a Windows security feature that prompts users for consent when an operation requires elevated privileges. When UAC is enabled, applications normally run with a standard user security context unless elevation is explicitly approved.

An administrator account can have two access tokens: a filtered standard token for everyday activities and an elevated token containing administrative privileges.

UAC configuration

One registry value used to check whether UAC is enabled is: 

HKEY_LOCAL_MACHINE\Software\Microsoft\Windows\CurrentVersion\Policies\System
EnableLUA = 1

A value of 1 indicates that UAC is enabled. A value of 0 indicates that it is disabled.

Another relevant setting is ConsentPromptBehaviorAdmin: 

HKEY_LOCAL_MACHINE\Software\Microsoft\Windows\CurrentVersion\Policies\System
ConsentPromptBehaviorAdmin = 5
  • 0: Do not prompt for elevation.
  • 1: Prompt for credentials on the secure desktop.
  • 2: Always notify when an administrator requests elevation.
  • 3: Similar to option 1, without using the secure desktop.
  • 4: Similar to option 2, without using the secure desktop.
  • 5: Default behavior: prompt for consent when a non-Windows binary requests elevation.

Other registry values

LocalAccountTokenFilterPolicy affects remote token filtering for local accounts. Its behavior should be considered in the context of remote administration and the account being used.

FilterAdministratorToken controls whether the built-in Administrator account receives a filtered token when logging on locally.

Access Tokens

When a user logs in to Windows, the operating system creates an access token representing that logon session. The token contains information such as the user's identity, group memberships and privileges. It also includes a logon SID that identifies the current logon session.

Consider a simplified example:

  1. A user enters a username and password to log in.
  2. Windows authenticates the credentials.
  3. The system creates an access token containing the user's SID, groups and privileges.
  4. When the user starts an application such as Excel, the process receives a primary token representing its security context.
  5. Windows uses that context when checking whether the process can access a file or perform an operation.

Types of Access Tokens

Primary Token

A primary token represents the security context of a process. It is associated with the identity, groups and privileges under which that process runs.

A simplified logon flow:

  1. Winlogon manages the interactive logon process.
  2. Credentials are passed to the Local Security Authority Subsystem Service (LSASS) for authentication.
  3. LSASS creates a primary token for the authenticated user.
  4. Windows starts the user's shell, such as Explorer, with the appropriate token.
  5. Applications launched from the shell normally inherit the relevant security context.

Impersonation Token

An impersonation token allows a thread to temporarily act under another user's security context. This is particularly relevant in client-server applications and Windows services.

  • Anonymous: Access without identifying the client.
  • Identification: The server can identify the client but does not access resources as that client.
  • Impersonation: The server accesses local resources using the client's security context.
  • Delegation: The server can act on behalf of the client when accessing remote resources, subject to the applicable security configuration.

Key takeaway

UAC and access tokens are closely related but serve different roles. UAC governs the elevation experience, while access tokens carry the security context that Windows uses when evaluating access to resources.
