PlaidCTF — Prospecting

An exploration of a constraint-based flag checker and a genetic algorithm approach.

Challenge Overview

The Prospecting challenge validates a candidate flag by evaluating a large collection of conditions over individual bytes in an input buffer.

The checks include direct byte comparisons, XOR operations and additions between selected positions. Each condition contributes to a score when it evaluates to true.

The source script defines a 64-character flag, the PCTF{ prefix and a closing brace. The validation function receives the encoded candidate and evaluates the constraints.

Constraint Evaluation

The conditions have several recurring forms: 

buf[index] == constant

(buf[index_a] ^ buf[index_b]) == constant

(buf[index_a] + buf[index_b]) == constant

buf[index_a] == buf[index_b]

These expressions can be interpreted as constraints over byte positions. Direct comparisons constrain a byte to a specific value, while XOR and addition expressions relate two positions.

The original challenge script contains a large number of these predicates. Keep the original prospect() function from the source notes here if you want the full constraint listing available in the published article.

Scoring Function

The source code uses a callback to count the number of successful conditions. The score is therefore the number of predicates that evaluate to true for a candidate. 

def get_score(buf):
    global score
    score = 0

    def fn_chal(condition):
        global score
        if condition:
            score += 1

    prospect(list(buf.encode()), fn_chal)
    return score

Genetic Algorithm

Instead of searching every possible 64-character string, the script uses a genetic algorithm. It maintains a population of candidate flags and evolves them over a number of generations.

The parameters in the original script are:

FLAG_LEN = 64
FLAG_PREFIX = "PCTF{"
FLAG_SUFFIX = "}"
CHARSET = string.printable.strip()

POP_SIZE = 400
GENERATIONS = 10000
MUTATION_RATE = 0.03
ELITE_COUNT = 100

Population initialization

The initial population is generated from random printable characters while preserving the required flag prefix and suffix. 

def random_flag():
    middle_len = FLAG_LEN - len(FLAG_PREFIX) - len(FLAG_SUFFIX)
    middle = ''.join(random.choices(CHARSET, k=middle_len))
    return FLAG_PREFIX + middle + FLAG_SUFFIX

Mutation

Mutation randomly changes characters in the body of a candidate. The prefix and suffix are kept unchanged. 

def mutate(flag):
    flag = list(flag)

    for i in range(len(flag)):
        if (
            random.random() < MUTATION_RATE
            and i >= len(FLAG_PREFIX)
            and i < FLAG_LEN - len(FLAG_SUFFIX)
        ):
            flag[i] = random.choice(CHARSET)

    return ''.join(flag)

Crossover

Crossover combines two parent candidates by selecting a split position and taking the prefix from one parent and the remaining part from the other. 

def crossover(parent1, parent2):
    idx = random.randint(
        len(FLAG_PREFIX),
        FLAG_LEN - len(FLAG_SUFFIX) - 1
    )

    child = parent1[:idx] + parent2[idx:]
    return child

Evolution loop

Each generation is scored and sorted. The highest-scoring candidates are retained as elites. New candidates are produced through selection, crossover and mutation. 

population = [random_flag() for _ in range(POP_SIZE)]

for gen in range(GENERATIONS):
    scored = [
        (flag, get_score(flag))
        for flag in population
    ]

    scored.sort(key=lambda x: x[1], reverse=True)
    best = scored[0]

    print(f"Generation {gen} | Score: {best[1]}")

    if best[1] >= 281:
        print(f"Flag: {best[0]}")
        break

    new_population = [
        flag for flag, _ in scored[:ELITE_COUNT]
    ]

    while len(new_population) < POP_SIZE:
        p1, p2 = random.choices(new_population, k=2)
        child = mutate(crossover(p1, p2))
        new_population.append(child)

    population = new_population

Notes and Limitations

The genetic algorithm is a heuristic search method. A high score indicates that many predicates are satisfied, but it does not automatically prove that the candidate is a valid flag unless the challenge's acceptance condition is also satisfied.

The source notes record a score threshold of 281. They do not establish a verified final flag or a complete successful solve, so this article does not claim one.

  • Identify contradictory or duplicated conditions.
